# Contributing to Trooth

Thanks for helping. These rules keep the open-source repos predictable.

## Before you open a pull request

Open an issue first for anything beyond a typo or a one-line fix. Substantial changes, and anything that touches a public interface, need a short discussion before code so review does not surprise you. Typos, broken links, and obvious doc fixes: open the PR directly.

## Commits must be signed

We require verified commits. Sign yours with GPG, SSH, or S/MIME so GitHub shows the "Verified" badge. Unsigned commits are not merged. See GitHub's guide on commit signature verification.

## Development setup

Each repo documents its own setup in its README. Clone, install, and run the test suite before you push.

## What we look for

- One concern per pull request. Small, reviewable diffs merge fast.
- Tests for behavior changes.
- No new dependencies without a reason in the PR description.
- Match the surrounding style. The linter is the authority; we do not bikeshed formatting.

## Security

Do not open a public issue for a vulnerability. Follow SECURITY.md and report privately to security@trooth.co.
